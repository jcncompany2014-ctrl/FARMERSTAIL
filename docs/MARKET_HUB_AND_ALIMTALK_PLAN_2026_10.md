# 마켓 통합 허브 + 알림톡 자동발송 기획

판매 채널: 자사몰(farmerstail.kr, 정기배송) · 네이버 스마트스토어 · 쿠팡 (운영 중) /
토스쇼핑 · 카카오쇼핑(톡스토어) · 카카오톡 선물하기 (입점 예정).

## 0. 결론 먼저

1. **알림톡은 자사몰 고객에게만** 보낸다. 쿠팡 구매자 번호는 050 안심번호라 알림톡이 원천적으로
   안 되고, 마켓들은 이미 자기 알림을 보내며, 마켓 경유 연락처는 "배송·상담" 목적 범위 안에서만
   쓸 수 있다. 자사몰이 우리가 직접 책임지는 고객이고, 결제 실패·가격 변경 고지가 실제로 필요한 곳이다.
2. **마켓 통합 허브(주문·문의 한 화면)는 만들 수 있다.** 단 두 가지 현실이 설계를 정한다.
   - 스마트스토어·쿠팡·토스쇼핑 **셋 다 호출 서버 IP를 등록해야** API가 열린다. Vercel은 나가는 IP가
     매번 바뀌므로, **고정 IP 작은 서버 1대(월 5~7천 원)** 를 "마켓 게이트웨이"로 둔다.
   - **리뷰는 어느 마켓도 API가 없다.** 통합 화면에서 리뷰는 각 마켓 관리 페이지 바로가기만 가능.
3. 카카오쇼핑·선물하기 API는 **대형 제휴사 대상 심사제**라 1인 판매자 승인 여부가 불확실하다.
   입점 시 연동 검토 신청을 넣되, 안 되면 연동대행사(사방넷 등) 키 연결 또는 엑셀 발송으로 운영한다.
4. 순서 추천: **① 알림톡(자사몰) → ② 게이트웨이 + 스마트스토어·쿠팡 주문·문의 → ③ 송장 일괄 처리 +
   토스쇼핑 → ④ 카카오(심사 결과에 따라)**.

## 1. 조사로 확인한 마켓별 사실

| | 스마트스토어 | 쿠팡(WING) | 토스쇼핑 | 카카오쇼핑·선물하기 |
|---|---|---|---|---|
| 주문 조회 | ✅ 변경분 폴링(1회 24h 창) | ✅ 발주서(31일·50건/쪽) | ✅ (31일·50건/쪽) | ✅ (24h·100건) — **심사제** |

추가 사실: 스마트스토어는 **문의 1영업일 미응답 제재**를 강화 중(경고 → 서비스 제한). 통합 문의함의
실질적 가치가 여기서 나온다 — 아침 브리핑·푸시로 "미답변 N건"을 놓치지 않게.

## 2. 알림톡 자동발송 (1단계)

### 2-1. 역할 분담
솔라피(또는 알리고)는 **전송만** 한다. 우리 시스템이 **언제·누구에게·무슨 내용**을 정하고, 실패 시
대체(푸시·메일)·중복 방지·기록을 책임진다. 솔라피엔 **멱등키가 없어서** 중복 방지는 우리 DB에서 한다.

### 2-2. 보낼 안내 (정보성 템플릿 후보 — 카카오 검수 대상)
| 코드 | 언제 | 핵심 변수 | 비고 |
|---|---|---|---|
| ORDER_PAID | 첫 박스 결제 완료 | 이름·주문번호·금액·발송 예정일 | |
| SHIPPED | 출고(송장 입력) | 택배사·송장 | 배송조회(DS) 버튼 |
| CHARGE_NOTICE | 정기결제 사전 고지(현행 D-2/1/0 리마인더) | 결제일·금액 | 전자상거래법 정기결제 고지 채널 |
| CHARGE_FAILED | 자동결제 실패 | 금액·재시도 일정 | 카드 재등록 버튼, **문자 대체발송 권장** |
| PRICE_CHANGE | 서포터즈·이벤트 가격 전환 예고 | 다음 결제일·금액 | 계약 조건 변경 고지 |
| CANCEL_REFUND | 주문 취소·환불 완료 | 금액 | |

반려 위험(쓰지 않음): 리뷰 작성 요청, 재구매·쿠폰·앱 설치 유도, 이벤트 공지 — 광고성은
**브랜드 메시지**(건당 100원, 마케팅 수신동의 필요)로 분리된다(친구톡은 2025-12-31 종료).
템플릿은 **승인 후 수정 불가** → 문구를 바꾸면 새 코드로 재등록(코드에 버전 관리).

### 2-3. 설계
- `lib/notify/` — 이벤트 하나를 푸시·메일·알림톡으로 나눠 보내는 라우터. 알림톡 실패 코드
  (3104 카톡 미사용·3107 차단)는 푸시/메일로 이미 커버되므로 **문자 대체는 CHARGE_FAILED만**.
- `message_log` 테이블 — (event_type, source_id, channel) unique로 한 번만 발송, 솔라피 messageId·
  상태·실패코드 기록. 어드민 **발송 내역** 화면(검색·재발송).
- `/api/webhooks/solapi` — 발송 결과 리포트 수신(200 아니면 5회 재시도 → messageId 기준 upsert, 시크릿 검증).
- 템플릿 정의는 코드 한 곳(`lib/notify/templates.ts`) — 카카오에 등록한 문구와 글자까지 같아야 발송됨.
  변수 누락·1,000자 초과·버튼명 변수는 테스트로 막는다.
- 발송 시간: 알림톡 08:00~20:50 제한 코드(3108)가 있음 — 청구 크론(09:10 KST)·어드민 출고는 범위 안.
- 개인정보처리방침에 **처리위탁(솔라피)** 추가 고지 필요.

### 2-4. 받는 번호 — ✅ 결정: 새 칸 없이 기존 "받는 분 연락처"
정기배송 주문 화면(OrderClient)에 **받는 분 · 연락처가 필수 칸으로 이미 있다**(프로필 번호가 비어 있으면
빈칸, 저장은 주문·구독의 recipient_phone). 정기배송 고객은 모두 번호가 있으므로 알림톡은 이 번호로 보낸다.
(앞서 "17명 중 1명"은 프로필 번호 칸 기준이라 판단 근거로 틀렸다.) 훅을 붙일 때 그 칸 아래에
"배송·결제 안내 알림톡도 이 번호로 가요" 한 줄 안내를 넣는다.

### 2-5. 구현 현황 (2026-09-28)
- ✅ `lib/notify/templates.ts` — 템플릿 6개 정본(문구·변수·버튼), 테스트 8.
- ✅ `lib/notify/alimtalk.ts` — 솔라피 SDK(solapi 6.0.1) 어댑터. 자리 잡기(unique) → 전송 → 기록, throw 없음,
  키·템플릿 ID 없으면 건너뜀.
- ✅ `message_log` 테이블(MCP 적용) · `/api/webhooks/solapi?token=` 결과 수신 · `/admin/messages` 준비 상태·발송 내역.
- ✅ 탈퇴 시 발송 기록 익명화. 규칙133.
- ⏳ 이벤트 훅(결제 완료·출고·사전 안내·결제 실패·가격 변경·취소) — **템플릿 승인 후** 붙인다(승인 문구 확정 뒤).
- ⏳ 처리방침 위탁 고지(솔라피) — 출시점검 세션이 docs/LEGAL_REVISION_2026_10.md 에 반영(14cdf587).

### 2-6. 사장님 준비 절차 (템플릿은 제가 API 로 등록)
1. solapi.com 사업자 회원 가입 → 소액 충전.
2. 콘솔 → 카카오 → 채널 연동: 검색용 아이디(@…) + 관리자 휴대폰 인증.
3. 콘솔 → API Key 발급 → 바탕화면 파일에 적기 → 제가 주는 스크립트가 Vercel 에 등록하고 파일 삭제
   (비밀값이 채팅을 거치지 않게 — 인스타 키 때와 같은 방식).
4. 제가 템플릿 6개를 API 로 등록·검수 요청(문구 오타 방지) → 카카오 검수 1~3영업일.
5. 웹훅 주소 1줄을 콘솔에 붙여넣기(스크립트가 만들어 줌). (선택) 발신번호 등록.

## 3. 마켓 통합 허브 (2~4단계)

### 3-1. 구조 — 고정 IP "마켓 게이트웨이"
```
[스마트스토어·쿠팡·토스 API] ⇄ (등록된 고정 IP) 게이트웨이 서버 ⇄ Supabase ⇄ Vercel 어드민
```
- **쉬운 설명**: 마켓들은 "미리 등록한 주소(IP)에서 오는 요청만" 받아 준다. 우리 사이트(Vercel)는 요청할
  때마다 다른 주소로 나가서(공용 택시) 등록이 불가능하다. 그래서 **주소가 안 바뀌는 작은 컴퓨터 한 대를
  클라우드에서 빌려**(자가용) 마켓과의 대화는 그 컴퓨터만 하게 한다. 우리 어드민은 그 컴퓨터가 가져다
  놓은 주문·문의를 DB 에서 읽기만 한다. 사장님 일은 클라우드 계정 만들기·서버 생성 버튼·나온 IP 를 마켓
  3곳에 등록하기까지, 설치·운영은 제가.
- 게이트웨이 = 월 5~7천 원짜리 고정 IP 서버 1대(예: AWS Lightsail 서울) 위의 작은 Node 작업자.
  5분마다: 변경 주문·새 문의 **가져오기** → Supabase 기록 / 어드민에서 쓴 답변·송장 **내보내기 큐** 처리.
- 마켓 키는 **게이트웨이에만** 둔다(Vercel·DB에 저장 안 함). 게이트웨이는 Supabase와만 대화.
- 대안 비교: Vercel 고정 IP 옵션은 **월 $100** — 과함. 고정 IP 프록시 서비스(월 2~3만 원대)도 가능하나
  게이트웨이가 폴링 주기 문제까지 함께 풀어서 더 싸고 단순.
- 호출 한도 준수(네이버 2 RPS 전체 합산·쿠팡 5 RPS 반복 초과 시 영구차단) → 게이트웨이가 줄 세워 호출.
- 키 만료 감시: 쿠팡 180일·네이버 휴면 → 만료 2주 전 사장님 푸시.

### 3-2. 데이터
- `market_orders` — 마켓·주문번호(unique)·상태·상품·수량·금액·주문일·송장. 구매자 개인정보는 **최소한**만,
  마켓별 보유기간(쿠팡: 정산 완료까지, 선물하기: 거래 종료 후 60일)에 맞춰 **자동 파기**.
- `market_inquiries` — 마켓·문의번호(unique)·종류(상품문의/고객문의/고객센터 이관/채팅)·상품·질문·
  **답변 기한**·답변·답변 시각.
- `market_outbox` — 어드민에서 누른 "답변 등록"·"송장 전송"이 쌓이는 큐(재시도·오류 기록).
- `market_sync_state` — 마켓·흐름별 마지막 조회 시각(24h 창 쪼개 백필).

### 3-3. 어드민 화면
- **통합 주문함**: 자사몰 + 마켓 주문을 한 표에(채널 배지), 상태별 필터, 송장 한 번 입력 → 해당 마켓으로 전송.
- **통합 문의함**: 미답변·기한 임박 순, 답변 쓰면 해당 마켓에 등록. 새 문의 → 사장님 앱 푸시,
  아침 브리핑에 "마켓 미답변 N건".
- **리뷰**: API 없음 → 마켓별 리뷰 관리 페이지 바로가기 버튼만.

### 3-4. 마켓별 순서
- 2단계: 스마트스토어 + 쿠팡 — 주문 수집 + 문의 수집·답변.
- 3단계: 송장 일괄 전송(3채널) + 토스쇼핑 추가(입점·토스페이 청약 후 키 발급).
- 4단계: 카카오쇼핑·선물하기 — 연동 검토 신청 결과에 따라 직접 연동 / 대행사 키 연결(인증키당 대행사
  최대 2~3곳) / 엑셀 일괄발송. 선물하기는 **수령인이 배송지를 입력해야** 주문이 넘어오고, 기한 내
  미입력 시 자동 취소 — 재고·생산은 "배송요청" 기준으로 잡는다.

| 카카오·선물하기 | 심사 필요 | ✅ 대행사로 연결 가능 |

→ **혼합안**: 스마트스토어·쿠팡·토스는 직접 구축, 카카오 두 채널은 심사 전까지 대행사 무료 플랜으로.

## 4. 비용 (월, 부가세 별도)
- 알림톡: **솔라피 13원/건**(SMS 18원·LMS 45원) / 알리고 6.5원(SMS 8.4원) / 카카오 공식 딜러 7~10원.
  월 500건 기준 솔라피 약 6,500원 · 알리고 약 3,300원. 월 기본료 없음. 하루 기본 한도 1,000건.
- 마켓 API: 무료로 보임(공식 요금 문구는 미확인).
- 게이트웨이 서버: 약 5~7천 원.
- 개발: 알림톡 3~4일(+템플릿 검수 1~3영업일 병행) · 게이트웨이+스마트스토어·쿠팡 1~1.5주 · 송장+토스 3~4일.

## 5. 사장님 결정 — ✅ 확정 (2026-09-28, "추천대로")
1. 순서: 알림톡 먼저 → 마켓 허브
2. 알림톡 대상: 자사몰 고객만
3. 발송사: 솔라피(코드는 교체 가능하게)
4. 번호: 새 칸 없이 기존 "받는 분 연락처"(§2-4)
5. 결제 실패만 문자 대체발송(발신번호 등록 시)
6. 마켓 허브: 직접 구축(고정 IP 게이트웨이) + 카카오는 대행사 혼합

## 6. 사장님 준비물(콘솔 작업 — 결정 후 캡처 안내)
- 알림톡: 발송사 가입·충전 → 카카오 채널 연동(검색용 아이디 @···, 담당자 휴대폰 인증) → 템플릿 6개 접수
  → (선택) 발신번호 등록 → 웹훅 URL 등록.
- 마켓: 게이트웨이 서버 생성(고정 IP 확인) → 스마트스토어 apicenter 내스토어 앱 등록(IP 등록) →
  쿠팡 WING API 키 자체개발 발급(IP 등록) → (입점 후) 토스셀러 연동관리 키 → 카카오쇼핑 연동 검토 신청.

## 7. 미확인·리스크
- 스마트스토어 주문의 구매자 전화가 실번호인지, 네이버 약관상 자체 알림 사용 가능 여부(원문 접근 실패).
- 알림톡 08:00~20:50 제한이 알림톡에도 적용되는지(3108 코드 존재).
- 솔라피 API에 IP 제한 설정 유무 — 있으면 알림톡 발송도 게이트웨이 경유.
- 카카오쇼핑 1인 판매자 연동 승인 여부·기간, "긴급알림 API" 성격.
- 토스쇼핑 리뷰·웹훅 부재 재확인(디스코드 문의).
- 스마트스토어 문의 지연 제재 시행일(자료 간 불일치).
